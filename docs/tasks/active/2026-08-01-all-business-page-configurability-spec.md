## 目标

将“所有用户可见功能页面的组件、表格和显示文字均可受控配置”补充为可实施、可验收的建设规范。每个页面都必须进入覆盖矩阵并声明配置等级；组件只能在白名单及兼容契约内替换；缺少组件所需权限时必须提示并在发布前阻断，界面配置不得自动授予权限。

## 范围

- 涉及模块：产品配置边界、后端配置校验、管理端/角色工作台/公共门户前端、动态表格、配置版本和验收；
- 预计文件：任务与需求索引、产品规范、角色数据范围、后端架构、前端架构、动态表单与表格、数据库设计、验收矩阵和上线清单；
- 数据/API/配置：本任务只定义页面注册、组件契约、权限缺口提示、表格和文案配置的建设边界，不新增运行时表、接口、权限标识或配置数据。

## 禁止范围

- 不修改 `backend/`、`frontend/`、`portal/` 或 `deploy/`；
- 不把页面配置建设为任意低代码平台，不允许上传或执行任意组件、HTML、CSS、JavaScript、SQL 或表达式；
- 不通过添加组件自动授予权限，不因配置显示扩大角色数据范围或绕过业务状态；
- 不修改 DYZ，不复制 DYZ 运行代码、数字主键、配置数据或生产参数；
- 不构建、不执行 SQL、不连接服务器、不部署；仅按用户授权执行本地分类提交，不推送 Git。

## 验收

- [x] 管理端、全部业务角色工作台和公共门户的用户可见功能页面必须进入覆盖矩阵，并声明稳定 `page_key`、配置等级、组件、表格、文案、必要项和不开放原因；
- [x] 组件注册表声明稳定 `component_key`、兼容组、数据契约、动作契约、所需权限、适用角色/页面和安全降级；
- [x] 添加组件时能按目标角色提示缺失权限；草稿可保留显式警告，发布前必须补齐权限，配置流程不能自动授权；
- [x] 所有业务数据表格使用统一受控配置边界，覆盖列、筛选、状态 Tab、分页、操作、固定文案、必要列和显示/导出分离；
- [x] 页面标题、字段/表头显示名、按钮、状态和提示文案可替换，但稳定键、权限标识、状态码、校验、安全警告和审计语义不可被文字覆盖；
- [x] 草稿、预览、服务端校验、发布、回滚、权限撤销后的运行时降级及覆盖完成度具有验收用例。
