# CREHN 安全与运维规范 V1.1

## 1. 安全原则

- 最小权限、默认拒绝、服务端裁定、全程审计；
- 身份、功能权限、数据范围和业务状态四层同时校验；
- 生产、测试、开发环境的数据库、Redis、对象存储、密钥和域名完全隔离；
- 密码、激活码、证件号、手机号、评分材料和未发布结果按敏感信息管理。

## 2. 账号与激活

- 每位参赛者保留正式账号，不能悄悄改成学校代报。
- 学校联络员可批量导入名单或生成一次性激活码，参赛者本人激活并设置密码。
- 激活码一次性、限时、不可在日志中记录明文；失败次数和发送频率受限。
- 省级管理员可以执行兜底激活、解锁或账号接管，但必须填写原因并形成高风险审计。
- 账号归属、学校关系与业务项目分离；人员换校或账号停用不能破坏历史记录。
- 密码重置、多因素认证（管理员和高权限角色优先）、会话失效和异常登录提醒使用框架安全能力统一实现。

## 3. 权限与数据隔离

- 角色和权限边界遵循 [角色与数据范围](../01-产品设计/CREHN_ROLE_DATA_SCOPE.md)。
- 超级管理员也应通过正常业务服务操作，紧急绕过必须单独审计。
- 学校只能访问本校名单、项目和批次；专家只能访问分配给自己的匿名项目；审核员只能访问其审核范围。
- 评分汇总员可以读取汇总所需数据，但没有配置规则、修改原始评分或直接发布结果的默认权限。
- 批量接口、导出接口、文件接口和统计接口执行与详情页相同的数据范围过滤。

## 4. 个人信息与匿名评审

- 证件号等高敏字段加密或令牌化存储，列表默认脱敏，导出单独授权。
- 匿名材料由服务端生成明确字段白名单，不依赖前端隐藏姓名/学校。
- 管理员配置匿名规则后生成版本；已开始评审的批次不能无痕修改。
- 日志、错误信息、缓存和前端埋点不得包含完整敏感信息。
- 规定数据保留期限、删除/匿名化流程和合规冻结机制。

## 5. 文件安全

- 对象存储私有化，上传后进行真实类型、大小、哈希和恶意内容检查；
- 临时签名地址短时有效，不作为业务数据保存；
- 下载和预览按当前请求重新鉴权，记录高敏导出；
- CMS 富文本和文件名经过清洗，防止脚本执行、路径穿越和内容嗅探；
- 具体规则见 [文件生命周期](../07-主题与文件/CREHN_FILE_LIFECYCLE.md)。

## 6. 接口与应用防护

- 认证、激活、验证码、搜索、上传、导出等接口限流；
- 写接口防重放并支持幂等；高风险操作要求二次确认或重新认证；
- 输入使用白名单校验，数据库使用参数化查询；
- CORS、Cookie、安全响应头、CSRF 策略按实际认证模式配置；
- 依赖、镜像和前端包进行漏洞扫描，生产禁用调试接口和默认口令。

## 7. 审计与告警

至少审计：

- 账号创建、激活、重置、接管、禁用；
- 角色、权限、数据范围和单位关系变更；
- 活动发布、配置版本、类别字段、附件和评分规则变更；
- 学校统一提交、审核退回、专家分配、评分提交/解锁、签名锁定；
- 结果计算、人工调整、发布、撤回；
- 文件下载/删除、数据导入导出、兼容迁移和系统配置。

连续登录失败、批量越权、异常下载量、任务积压、扫描失败、存储异常和备份失败应触发告警。

## 8. 备份与恢复

- 数据库、对象存储、配置、密钥元数据和迁移清单分别制定备份策略；
- 备份成功不等于可恢复，必须定期在隔离环境执行恢复演练；
- 定义 RPO、RTO、保留周期、异地副本和责任人；
- 数据库恢复后校验文件绑定、配置版本、评分签名表、结果版本和审计链；
- 恢复演练不得覆盖生产或 DYZ 环境。
- 每个环境只保留本项目目录内最近3个“成功且完整”的应用回滚点；只有产物、Compose、受限环境备份、镜像引用/摘要、所需数据库 dump、本地持久化文件或对象存储策略、校验文件全部验证通过并写入 `SUCCESS` 标记后才计数。
- 失败或 `.incomplete-*` 目录不能挤掉有效回滚点；清理只删除本项目第4个及更早的成功完整回滚点，不执行 Docker 全局清理。
- 应用回滚恢复旧环境文件和旧镜像后重新验收，不自动恢复数据库或 OSS；数据库/OSS恢复需要独立影响分析、备份校验和授权。

## 9. 监控

监控至少覆盖：

- API 可用性、延迟、错误率、鉴权失败；
- JVM、数据库连接池、SQL 慢查询、Redis、磁盘与对象存储；
- 上传/扫描/转码、导入导出、通知和定时发布任务；
- 报名量、提交量、待审核量、评分进度等业务健康指标；
- 备份年龄、证书到期、队列积压和定时任务漏跑。

日志、指标和追踪使用统一请求编号关联，敏感值在采集前脱敏。

## 10. 部署与事件响应

- 构建产物、配置、SQL/数据迁移和对象存储策略分别有版本和校验值；
- 发布遵循 [迁移与发布](../03-数据库/CREHN_MIGRATION_RELEASE_RULE.md)，生产操作必须另行授权；
- 灰度/维护窗口、健康检查、回滚条件和负责人在发布前确认；
- 安全事件按发现、止损、取证、修复、恢复、复盘处理，禁止为“快速恢复”删除审计证据。
- TEST 固定为独立 Compose 项目 `crehn-test` 和目录 `/srv/crehn-test`，使用 `28181/29000/29001`，独立 MariaDB、Redis、MinIO、网络、数据和备份；部署前后比较项目A容器ID、镜像、健康、端口、挂载、重启和 OOM 状态。
- TEST 当前不增加独立虚拟磁盘；本地仅用于程序测试。构建资源接受“约8 GiB内存+2 GiB Swap”或“约6 GiB内存+4 GiB Swap”二选一，且全机同一时间只允许一个项目执行构建；不满足时构建入口必须阻断。
- PROD 使用专用 ECS 2、独立 Compose 和阿里云 OSS，不部署 MinIO，不从源码执行 Maven、pnpm、Vite 或 Docker build；反向代理、80/443、DNS、安全组和证书继续单独确认。
- `deploy/.env` 只保存 TEST/ECS 2 的 SSH目标与认证信息；`deploy/env/test.env` 和 `deploy/env/prod.env` 分别保存运行配置。真实文件不进入Git，Linux落盘为 `root:root:600`，SSH密码只通过 `SSH_ASKPASS` 传递且不得进入远端运行环境。
- 统一入口区分只读预检、资产暂存、本地顺序构建、本地部署、健康验收、生产预检、生产发布、数据库、回滚和备份维护；资产暂存、构建、部署、SQL、生产发布、回滚和清理分别要求 `Apply` 与精确确认串。

## 11. 分层限制与建议初始值

数值限制按“平台安全上限 → 系统策略 → 活动规则”解析，最终采用最严格有效值。配置修改必须回读、审计和版本化。

| 项目 | 建议初始值 | 配置层 |
| --- | --- | --- |
| 学校目录 | 1000所；活动默认全部启用学校 | 系统/活动 |
| 报名容量验收 | 500并发在线、100并发提交或上传初始化、持续30次写入/秒 | 运维与压测 |
| 单文件 | 活动默认1GB，平台硬上限2GB | 活动/环境 |
| 单项目附件 | 默认5GB | 活动 |
| 批量上传 | 默认100个文件、逻辑总量10GB | 活动 |
| 浏览器 | Chrome、Edge、Firefox最近两个大版本；Safari 16+ | 构建与验收 |
| 分辨率 | 后台最低1280×720；门户最低360×640 | 验收 |
| 临时/失败/导出/回收 | 24小时/7天/7天/30天 | 文件策略 |
| 业务附件 | 届次结束后5年 | 档案策略 |
| 审计、签名表、发布结果 | 10年或主办方确认的长期期限 | 档案策略 |
| 生产RPO/RTO | 平时1小时、关键期15分钟；RTO 4小时 | 运维目标 |
| 测试RPO/RTO | 24小时/1个工作日 | 运维目标 |

并发值是容量验收目标，不使用一个简单总人数开关拒绝“第501人”。网关限流、用户/IP限流、线程池、连接池和队列分别配置。缩短保留期限不能立即清理历史数据，必须先预览影响并单独确认。

## 12. 消息渠道

- 初期站内消息启用；短信和邮件在真实供应商账号配置前保持关闭。
- 模板可选择渠道，但供应商、SMTP、密钥、限流和超时属于环境配置。
- 测试适配器必须明确标识 `TEST`，不得伪造生产发送成功。
- 任一渠道的发送、失败、重试和最终状态均可审计；未经配置不静默切换渠道。
