# CREHN 对 DYZ 功能覆盖矩阵 V1.1

## 1. 用途

本矩阵依据当前 DYZ 艺术评审前后端功能面建立，用于防止 CREHN 重构时漏掉已有有效能力。它说明“CREHN 必须具备什么”，不表示这些能力已经完成代码实现。

处理方式：

- `CORE`：作为 CREHN 核心领域重新实现；
- `SHARED`：优先复用 RuoYi-Vue-Plus 或 CREHN 共享组件；
- `ADAPTER`：仅在兼容适配器中解析 DYZ 格式；
- `MIGRATION`：通过独立历史迁移批次处理；
- `REPLACE`：保留业务目标，但用更清晰的 CREHN 模型替代 DYZ 实现。

## 2. 活动和规则配置

| DYZ 功能面 | CREHN 处理 | 约束 |
| --- | --- | --- |

### 7.1 业务页面表头与表格配置覆盖明细

下表用于登记当前导航中的 8 个业务页面。它是功能覆盖说明，不代表运行时统一配置已经完成；页面只有在注册稳定 `page_key`、表格键、默认配置、权限校验和浏览器验收后，才能标记为已接入。

## 8. 兼容包与历史迁移覆盖

标准活动包可承载活动基础、类别、字段、成员、通用表格、附件、名额/报送、审核/评分/结果规则、页面配置、主题、通知模板、门户内容和资源。

以下运行数据不混入普通配置包，使用 `MIGRATION`：

- 单位、账号映射和参赛者身份；
- 作品、成员、子表、附件和学校提交批次；
- 审核/评审分配、审核记录、评分、签名资产和签名评分表；
- 汇总快照、结果版本、奖项、展演顺序、消息和审计附件。

密码、令牌、会话、验证码、对象存储凭据和临时 URL 永不迁移。

## 9. 开发使用规则

- 新建 CREHN 模块或页面前，先在本矩阵定位对应能力和处理方式。
- DYZ 出现新功能时先判断其业务价值，再更新矩阵；不得直接把 DYZ 代码复制进 CREHN。
- 功能验收以 [验收矩阵](../11-验收/CREHN_ACCEPTANCE_MATRIX.md) 为准。
- 本矩阵出现 `CORE` 不代表已实现；完成状态必须有代码、测试和运行证据。
