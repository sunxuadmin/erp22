# CREHN 产品设计规范

## 1. 产品范围

CREHN V1 覆盖以下完整能力：

1. 赛事、届次、活动及生命周期管理；
2. 独立公共门户、栏目、文章、媒体和组件化首页；
3. 全省学校清单、单位资料、学校账号和账号安全；
4. 参赛者名单、一次性激活码、本人账号和本人填报；
5. 类别树、动态字段、成员表、通用表格和附件规则；
6. 作品草稿、提交、撤回、学校审核推荐和学校最终批次提交；
7. 活动学校范围、名额、比例和报送规则；
8. 省级形式审查、审核员分配和结论撤回；
9. 专家分配、回避、任务工作台、评分和签名评分表；
10. 只读评分汇总、结果就绪检查、结果生成和发布；
11. 奖项规则、评分调整审计和展演顺序；
12. 角色首页、页面与类别布局、公共样式和配置迁移；
13. 消息中心、通知模板、导出任务、回收站和操作审计；
14. DYZ 活动配置导入及历史数据迁移。

签名评分表能力包括评分表模板、个人手写签名库、默认签名、无签名提交单、历史快照、本人撤回和管理员强制撤回。通知能力包括通知模板、站内消息、发布消息、已读状态、失败重试和发送审计。

详细页面字段和按钮以 `CREHN-功能结构与页面字段规格说明书-审查稿V0.2.docx` 为产品基线。

当前 DYZ 功能逐项处理方式见 [CREHN 对 DYZ 功能覆盖矩阵](CREHN_DYZ_FUNCTION_COVERAGE.md)。

## 2. 核心业务不变量

- 参赛者必须使用本人激活的正式账号填报，学校不能无痕代报。
- 学校只能查看和处理本校账号、参赛者、作品与最终提交批次。
- 专家只能查看当前有效分配；匿名模式下学校、作者、联系人和文件元数据由服务端裁剪。
- 作品必须经过参赛者提交、学校审核推荐和学校最终提交，才能进入省级形式审查。
- 形式审查通过的作品才能进入专家评审分配。
- 评分草稿不进入正式汇总；正式汇总只读取有效已提交评分或已签评分表快照。
- 评分汇总与评审结果是两个模块：前者只读审计，后者负责规则、生成、锁定和发布。
- 结果生成与结果发布分离；发布只针对已锁定版本。
- 已签评分表、学校最终提交批次和已发布结果不得原地改写。
- 删除默认进入回收站；存在历史业务引用时禁止永久删除。

## 3. 配置化边界

可以配置：

- 时间窗口、学校范围、类别、名额、字段、布局、成员和附件要求；
- 审核和评审范围、专家数量、评分方式、可见性和签名策略；
- 奖项规则、门户内容、角色首页、系统骨架、导航模式、页面/类别布局、表格列、状态文案和公共样式；
- 通知模板、导出列和预警阈值。

必须由代码保证，不能交给任意配置：

- 身份认证、学校数据隔离、专家任务隔离；
- 状态合法转换、幂等、并发锁和事务；
- 密码、激活码、文件、导出和敏感信息安全；
- 已签评分、提交快照和发布结果不可变；
- 审计日志的完整性；
- 导入格式校验、版本协商和资源校验。

所有业务角色界面采用管理员维护的受控可视化配置。配置只能从已注册的页面、组件、字段、表格列和动作中选择，可调整显示、名称、顺序、尺寸、位置和主题；不能创建后端不存在的动作，不能授予权限、扩大数据范围、绕过状态机或执行任意 CSS、JavaScript、SQL 和表达式。

管理端、全部业务角色工作台和公共门户的用户可见功能页面必须进入页面配置覆盖矩阵，并声明稳定 `page_key`、配置等级、允许组件、表格、显示文案、必要项和不开放配置的原因。业务首页、列表、详情、提交、审核、评分、汇总、结果和门户内容页按受控能力完整配置；账号安全、权限、审计和系统配置页只开放不影响安全语义的显示配置；登录回调、错误处理、迁移和运维页保持代码控制。未登记页面不得自行创建另一套配置来源。

组件替换只能在声明兼容关系的数据契约、动作契约和权限要求内进行。管理员为目标角色添加组件时，配置器必须检查组件声明的功能权限和适用数据范围；缺少权限时明确列出缺口并提示先增加权限，允许草稿保留带警告的未满足组件，但发布前必须补齐。界面配置不得自动授权，权限授予仍由独立的角色权限流程完成并审计。

允许替换的文字仅限页面标题、说明、分区标题、字段和表头显示名、筛选标签、按钮、状态显示名、空状态、帮助和确认提示等呈现文案。`page_key`、`component_key`、`field_key`、`action_key`、权限标识、API/数据库字段、状态码、校验规则、安全警告和审计语义不得被显示文字覆盖；状态可改显示名称和语义颜色，不能改变状态机含义。

按钮最终可用必须同时满足：后端功能权限、当前角色数据范围、业务状态允许和已发布界面配置要求显示。配置隐藏不等于撤销权限，配置显示也不等于获得权限。

配置继承顺序为“系统默认 → 活动 → 角色 → 页面 → 类别覆盖”。每个页面必须显示当前有效配置来源，用户个人偏好只可影响管理员允许的临时列宽、折叠和密度，不能覆盖菜单、品牌、组件可见性、权限和流程。

## 4. 活动默认值

- 报名默认开放时间：`2026-09-01 00:00`，允许活动管理员调整。
- 默认学校范围：全部启用学校。
- 参赛者账号方式：学校联络员导入名单或生成一次性激活码，参赛者本人激活。
- 省级管理员提供异常名单、激活和账号恢复兜底，但所有操作必须记录原因。

默认值只用于新活动，不能覆盖已经运行活动的有效配置。

## 5. 产品验收原则

每项业务能力必须同时说明：

- 谁可见；
- 页面字段和按钮；
- 后端权限和数据范围；
- 允许状态；
- 成功结果和失败结果；
- 审计记录；
- 历史数据影响；
- 浏览器、接口或数据回读验证方法。
