# CREHN 产品设计规范

## 1. 产品范围

CREHN V1 覆盖以下完整能力：

1. 赛事、届次、活动及生命周期管理；
2. 独立公共门户、栏目、文章、媒体和组件化首页；
3. 全省学校清单、单位资料、学校账号和账号安全；
4. 参赛者名单、一次性激活码、本人账号和本人填报；
5. 类别树、动态字段、成员表、通用表格和附件规则；
6. 作品草稿、提交、撤回、学校审核推荐和学校最终批次提交；
7. 活动学校范围、名额、比例和报送规则；
8. 省级形式审查、审核员分配和结论撤回；
9. 专家分配、回避、任务工作台、评分和签名评分表；
10. 只读评分汇总、结果就绪检查、结果生成和发布；
11. 奖项规则、评分调整审计和展演顺序；
12. 角色首页、页面与类别布局、公共样式和配置迁移；
13. 消息中心、通知模板、导出任务、回收站和操作审计；
14. DYZ 活动配置导入及历史数据迁移。

签名评分表能力包括评分表模板、个人手写签名库、默认签名、无签名提交单、历史快照、本人撤回和管理员强制撤回。通知能力包括通知模板、站内消息、发布消息、已读状态、失败重试和发送审计。

详细页面字段和按钮以 `CREHN-功能结构与页面字段规格说明书-审查稿V0.2.docx` 为产品基线。

当前 DYZ 功能逐项处理方式见 [CREHN 对 DYZ 功能覆盖矩阵](CREHN_DYZ_FUNCTION_COVERAGE.md)。

## 2. 核心业务不变量

- 参赛者必须使用本人激活的正式账号填报，学校不能无痕代报。
- 学校只能查看和处理本校账号、参赛者、作品与最终提交批次。
- 专家只能查看当前有效分配；匿名模式下学校、作者、联系人和文件元数据由服务端裁剪。
- 作品必须经过参赛者提交、学校审核推荐和学校最终提交，才能进入省级形式审查。
- 形式审查通过的作品才能进入专家评审分配。
- 评分草稿不进入正式汇总；正式汇总只读取有效已提交评分或已签评分表快照。
- 评分汇总与评审结果是两个模块：前者只读审计，后者负责规则、生成、锁定和发布。
- 结果生成与结果发布分离；发布只针对已锁定版本。
- 已签评分表、学校最终提交批次和已发布结果不得原地改写。
- 删除默认进入回收站；存在历史业务引用时禁止永久删除。

## 3. 配置化边界

可以配置：

- 时间窗口、学校范围、类别、名额、字段、布局、成员和附件要求；
- 审核和评审范围、专家数量、评分方式、可见性和签名策略；
- 奖项规则、门户内容、页面布局、状态文案和公共样式；
- 通知模板、导出列和预警阈值。

必须由代码保证，不能交给任意配置：

- 身份认证、学校数据隔离、专家任务隔离；
- 状态合法转换、幂等、并发锁和事务；
- 密码、激活码、文件、导出和敏感信息安全；
- 已签评分、提交快照和发布结果不可变；
- 审计日志的完整性；
- 导入格式校验、版本协商和资源校验。

## 4. 活动默认值

- 报名默认开放时间：`2026-09-01 00:00`，允许活动管理员调整。
- 默认学校范围：全部启用学校。
- 参赛者账号方式：学校联络员导入名单或生成一次性激活码，参赛者本人激活。
- 省级管理员提供异常名单、激活和账号恢复兜底，但所有操作必须记录原因。

默认值只用于新活动，不能覆盖已经运行活动的有效配置。

## 5. 产品验收原则

每项业务能力必须同时说明：

- 谁可见；
- 页面字段和按钮；
- 后端权限和数据范围；
- 允许状态；
- 成功结果和失败结果；
- 审计记录；
- 历史数据影响；
- 浏览器、接口或数据回读验证方法。
