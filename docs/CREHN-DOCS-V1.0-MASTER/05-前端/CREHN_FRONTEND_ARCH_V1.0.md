# CREHN 前端架构规范 V1.1

## 1. 应用边界

CREHN 前端分为三个可独立构建的边界：

- `crehn-portal`：独立门户，负责首页、文章、媒体、活动公开信息、结果公开查询及登录入口。
- `crehn-admin`：登录后的统一业务端，根据角色呈现参赛者、学校、审核、评分、汇总和管理工作台。
- `crehn-ui`：共享设计令牌、基础组件、业务组件和动态渲染组件，不包含角色权限判断和具体活动数据。

与 DYZ 可以复用经过重构的通用组件设计，但不得从 DYZ 运行目录引用代码、环境变量或后端地址。

## 2. 角色工作台

| 工作台 | 核心页面 |
| --- | --- |
| 参赛者 | 激活账号、我的报名、作品填报、成员/附件、提交记录 |
| 学校单位 | 参赛名单、校内审核、退回、推荐、统一提交、统计导出 |
| 审核员 | 待审项目、材料预览、审核结论、退回补正、审核记录 |
| 评分员 | 已分配项目、匿名材料、单项目评分、草稿、提交与签名 |
| 汇总员 | 评分进度、签名表、缺评/异常分、只读汇总与导出 |
| 结果管理员 | 结果就绪、奖项规则、结果草案、复核、锁定、发布与撤回 |
| CMS 编辑 | 栏目、文章、媒体和首页内容草稿与送审 |
| CMS 发布 | 内容审核、定时发布、下线和回滚 |
| 监督审计员 | 账号、权限、导入、审核、评分、结果、配置和发布日志，只读 |
| 活动管理员 | 活动配置、类别字段、附件评分、分配、门户、角色界面和结果管理 |
| 次活动管理员 | 复用活动管理员页面，但只显示明确授予的菜单、动作和数据范围 |
| 超级管理员 | 赛事、单位、账号、全局字典、系统运维和审计 |

一个账号可以拥有多个角色，但菜单、数据查询和可执行动作必须按当前角色上下文和服务端授权共同决定。

## 3. 路由与权限

- 路由按业务模块懒加载，公共路由、认证路由、角色工作台路由明确分层。
- 菜单和按钮权限来自服务端；前端隐藏只用于减少误操作。
- 页面每次进入和关键动作前都依据服务端返回的 `allowedActions`、状态和版本刷新可用按钮。
- 403、状态冲突、版本冲突、登录失效分别处理，不统一伪装为“操作失败”。

## 4. 动态表单与表格

- 使用统一 Schema 渲染表单、成员表、附件要求和业务列表。
- 字段 `fieldKey` 是稳定业务标识，显示名称和排序可变但不能代替标识。
- 页面保存时提交配置版本；版本冲突提示刷新或对比，不静默覆盖。
- 历史项目按提交快照显示，不使用最新 Schema 猜测旧字段。
- Excel 导入必须先预检并展示逐行错误，确认后再入库。

详细规则见 [动态表单与表格](../06-动态引擎/CREHN_DYNAMIC_FORM_TABLE.md)。

## 5. 共享组件归属

适合进入 `crehn-ui`：

- 文件上传/预览、状态标签、权限动作条、Schema 表单、可配置表格；
- 成员编辑器、附件清单、评分表、进度反馈、导入结果；
- 主题令牌、响应式布局、空状态、错误状态、打印样式。

不适合进入 `crehn-ui`：

- 活动专用字段和业务文案；
- 角色数据权限；
- DYZ 格式分支；
- API 地址、存储路径和环境配置。

## 6. 配置页面

### 6.1 配置中心与继承

管理员通过统一“工作台配置”维护以下范围：

1. 角色首页；
2. 页面与类别布局；
3. 角色工作台外观；
4. 公共样式与主题；
5. 独立门户布局；
6. 表格列与筛选；
7. 表单字段与附件展示；
8. 按钮及状态文案；
9. 配置迁移、导入和导出；
10. 版本、发布和回滚。

配置继承顺序为“系统默认 → 活动 → 角色 → 页面 → 类别覆盖”。配置页必须显示当前范围、继承来源、草稿版本和线上已发布版本，不能把浏览器本地状态表现为权威配置。

### 6.2 角色首页和业务页面

角色首页可以从白名单组件中配置公告、当前活动、日历/倒计时、统计卡片、分类进度、待办、快捷入口、最近操作、消息、异常提示和数据列表。组件可以调整显示、顺序、栅格宽度和受限样式，只能读取该角色服务端数据范围内的聚合数据。

业务页面可以配置页面标题、说明、筛选区、状态 Tab、表格/卡片模式、详情分组、表单分组、附件区位置、空状态、帮助文案及已注册动作的显示顺序。活动字段的必填、校验和提交规则仍以动态 Schema 与服务端规则为唯一来源。

### 6.3 表格列设计器

表格列配置必须支持：

- 页面默认和类别维护两个层级；
- 页面真实效果预览及全部列完整性检查；
- 拖拽排序、显示/隐藏、固定左侧/右侧、默认宽度和最小宽度；
- 表头文字、空数据提示、默认排序、分页大小及小屏折叠策略；
- 状态列引用活动级统一状态文案和颜色；
- 操作列引用已注册 `action_key`，仅配置名称、顺序、位置和样式；
- 恢复当前列默认值、恢复页面默认值和从隐藏列恢复。

项目编号、项目名称、状态等页面必要识别列可调整但不得从 Schema 永久删除。隐藏列不删除业务数据；显示列和导出列分别配置，不能因页面隐藏自动减少审计导出范围。

### 6.4 角色系统骨架

每个业务角色可以选择左侧导航、混合导航或顶部导航，并配置：

- 左上品牌区是否显示，Logo、活动名称、角色名称或受限自定义文字来源；
- 侧栏折叠时仅显示 Logo 或保留品牌简称；
- 顶栏高度、侧栏宽度、内容最大宽度、页面密度和菜单紧凑度；
- 菜单分组、图标、显示名称、顺序、面包屑和页面标签栏；
- 角色强调色以及主题允许覆盖的语义令牌；
- 可点击区域预览、结构预览和真实角色预览。

菜单配置只能排列服务端为该角色返回的菜单，不能新建权限或显示越权路由。公共门户使用独立骨架和发布版本，不与登录后角色工作台混用。

### 6.5 草稿、发布与回滚

- 编辑保存为草稿，不直接影响正在使用的角色；
- 发布前以指定角色和活动预览，并检查未知组件、重复列、必要列、无效动作、权限和配置版本；
- 发布生成不可变快照，记录操作者、时间、原因、差异和来源版本；
- 保存后必须服务端回读规范化值，明确显示“已保存草稿”或“已发布版本”；
- 回滚以历史发布版本为来源创建新的发布版本，不篡改旧版本；
- 恢复默认值必须明确系统、活动、角色、页面或类别作用范围，并显示影响统计；
- 导入 DYZ 配置先生成映射报告，未知 `role_key`、`page_key`、组件、列或动作必须阻断或进入显式待映射，不能静默丢弃。

按钮最终可用条件为“后端功能权限 + 当前数据范围 + 业务状态允许 + 已发布界面配置显示”。任何前端显示和隐藏都不能替代服务端鉴权。

## 7. 文件体验

- 上传前展示类型、大小、数量、命名和模板要求。
- 上传过程显示哈希/传输/扫描/预览状态；扫描未通过不得当作有效附件。
- 预览和下载每次向服务端申请授权，不长期缓存临时签名地址。
- 删除采用回收语义并显示业务影响；已提交、评分或发布材料按状态限制操作。

## 8. 质量要求

- TypeScript 严格模式，API 类型与 Schema 类型集中维护。
- 支持常用桌面分辨率和窄屏操作，不以隐藏关键按钮解决拥挤。
- 表单具备键盘操作、标签关联、错误聚焦和必要的无障碍提示。
- 大表格采用服务端分页/筛选，固定关键列并允许用户恢复默认列宽。
- 测试至少覆盖规则函数、权限动作映射、核心组件和关键角色流程；真实浏览器验证不能由构建成功替代。
