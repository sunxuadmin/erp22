# CREHN 动态表单与表格规范 V1.1

## 1. 目标

动态引擎用于配置不同活动、类别和角色的字段、成员表、附件及列表显示。它是受约束的业务 Schema，不是任意低代码平台。

## 2. Schema 结构

每份 Schema 至少包含：

- `schemaVersion`：Schema 协议版本；
- `configVersionId`：所属活动发布版本；
- `scope`：活动、类别、阶段、角色、页面；
- `fields`：字段定义；
- `layout`：分组、栅格、顺序和展示规则；
- `validation`：跨字段业务校验；
- `table`：列表列、筛选、排序和导出映射；
- `compatibility`：外部稳定编码及版本映射。

字段至少包含：`fieldKey`、显示名称、类型、是否必填、默认值、选项来源、提示、单位/后缀、长度或数值范围、脱敏级别、可见/可编辑角色、排序、启停和兼容编码。

## 3. 支持字段

- 单行文本、多行文本、富文本；
- 整数、小数、金额、百分比；
- 单选、多选、下拉、级联、开关；
- 日期、日期时间、时间、时长；
- 手机号、邮箱、证件号等受控格式；
- 字典、学校、地区、用户等引用选择；
- 图片、文件、音视频附件引用；
- 成员表、通用子表和只读计算字段。

不得允许管理员注入任意 JavaScript、SQL、HTML 或后端表达式。计算与显示条件只能使用白名单操作符和受控字段引用。

## 4. 校验规则

- 单字段：必填、长度、范围、精度、格式、选项、附件数量和大小；
- 跨字段：条件必填、互斥、总数、成员类型数量、日期先后；
- 业务规则：活动时间、类别限额、学校范围、重复报名、项目状态；
- 服务端必须执行与前端同等级或更严格的校验，并返回字段级错误。

修改规则时必须说明对历史草稿、已提交项目和导入模板的影响。

## 5. 显示与编辑规则

- `visibleWhen` 只决定展示，不能替代服务端数据权限。
- `editableWhen` 同时受角色、数据范围、项目状态、阶段时间和配置版本约束。
- 敏感字段按角色脱敏，导出时重新授权。
- 已发布后删除字段采用停用和保留历史定义，不物理删除历史语义。

## 6. 成员表

支持 DYZ 已有的“系统成员表”和“通用表格模板”思想：

- 成员类型可配置：学生、作者、指导教师、完成人及自定义类型；
- 配置显示名称、稳定编码、适用字段、是否启用和默认类型；
- 配置总人数及各成员类型的最小/最大人数；
- 学生/教师可采用不同字段集合；
- 保留成员顺序、成员角色、所属单位和必要的身份去重；
- 允许管理员关闭成员模块，但不得导致历史成员数据无法查看。

## 7. 通用子表

通用子表支持列定义、必填、数据类型、字典、唯一组合、行数范围、排序和说明。每行有稳定行标识，禁止仅靠数组下标更新。

## 8. 动态表格

所有业务数据表格必须登记稳定表格键并进入页面配置覆盖矩阵；不能接入统一配置的安全、运维或框架表格必须说明原因。每个已登记业务页面可配置：

- 列名、字段、宽度、固定、对齐、排序、脱敏和格式化；
- 默认筛选、角色可用筛选、状态 Tab、分页；
- 行操作、批量操作和操作权限；
- 导出列和列级敏感权限；
- 表头、筛选标签、状态显示名、空数据、加载/错误、行/批量操作和确认提示等固定显示文案；
- 用户个人列宽/显示偏好，可恢复页面默认值。

页面布局配置不得改变后端数据权限或业务状态。

列、筛选和操作只能引用已注册的 `field_key`、`column_key` 和 `action_key`。配置器为目标角色启用需要额外权限的操作列或组件时，必须列出缺失权限并提示先授权；缺口可保留在警告草稿中，发布前必须由服务端校验并阻断。权限配置保持独立，表格或页面配置不得自动写入角色权限。

显示文案可替换但不改变字段类型、状态码、权限标识、数据脱敏、校验和导出敏感级别。状态标签可配置名称和语义颜色，筛选值、接口参数和服务端状态机仍使用稳定编码。

## 9. Excel 模板与导入

- 模板必须绑定活动配置版本、类别、成员/子表定义和模板版本。
- 支持后台上传模板文件并标记用途、版本、适用范围和有效期；下载时使用 CREHN 文件引用。
- 可由系统根据 Schema 生成标准模板，也可在受控占位符范围内使用管理员模板。
- 导入流程为：上传 → 病毒扫描 → 结构预检 → 行级校验 → 差异预览 → 用户确认 → 幂等写入 → 结果报告。
- 支持“新增”“仅更新匹配项”“新建独立活动后导入”等明确模式，不默认覆盖现有数据。
- 错误报告必须包含工作表、行、列、错误码和可理解说明。
- 成员或附件批量上传支持按稳定字段键和文件名规则预览匹配；只有用户确认的精确匹配才建立绑定，未匹配、重复匹配和歧义项进入结果报告。

## 10. 发布与历史

- 草稿 Schema 可编辑；活动发布后生成不可变快照。
- 项目首次提交记录其 Schema 和规则快照；后续补正仍可追溯前后版本。
- 历史渲染器至少支持当前及承诺的旧版 Schema；不支持的版本必须阻止导入并给出升级路径。
- 外部包中的字段编码先经兼容映射，再进入内部模型。

## 11. 安全和验收

- Schema、模板、字典和引用对象均需按活动和角色授权。
- 富文本经过服务端清洗；文件字段只保存文件标识，不保存永久公开 URL。
- 必测：字段增删停用、条件必填、成员数量、子表唯一性、模板版本错误、逐行错误、重复导入、历史回显、敏感字段、角色只读及版本冲突。
