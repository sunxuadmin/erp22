# CREHN 版本与历史快照策略

## 1. 原则

- 可编辑配置与正式运行快照分离。
- 历史数据按创建时有效版本解释，不读取当前配置重新计算。
- 已提交、已签名、已生成和已发布对象使用追加版本，不原地覆盖。
- 每个版本记录创建人、创建时间、来源版本、变更说明和内容指纹。

## 2. 版本对象

| 对象 | 版本键 | 冻结时点 | 后续修改 |
|---|---|---|---|
| 活动配置 | `activity_config_version` | 管理员发布配置 | 创建新版本 |
| 动态字段/成员/表格/附件规则 | 随活动配置版本 | 配置发布 | 创建新版本 |
| 参与者资料确认 | `participant_profile_version` | 本人确认 | 新确认版本 |
| 作品快照 | `project_snapshot_version` | 参赛者提交 | 退回后新版本 |
| 学校提交批次 | `school_submission_batch_version` | 学校最终提交 | 新批次取代 |
| 审核记录 | 独立审计记录 | 每次结论 | 追加撤回记录 |
| 评审任务 | `assignment_version` | 分配生效 | 新版本或停用 |
| 专家评分 | `score_version` | 每次保存/提交 | 追加版本 |
| 签名评分表 | `signed_sheet_version` | 统一提交签字 | 永久快照 |
| 结果 | `result_version` | 生成 | 锁定后新版本 |
| 门户内容 | `content_version` | 发布 | 新草稿版本 |

## 3. 活动配置发布

草稿配置可以多次保存。发布配置时：

1. 服务端归一化全部配置；
2. 校验类别、字段、表格、附件和规则引用；
3. 生成不可变 JSON 快照和 SHA-256；
4. 创建配置版本；
5. 将活动当前版本指针指向新版本；
6. 写入操作审计。

已有作品继续引用原配置版本。新草稿默认使用当前有效版本。

## 4. 快照内容

作品提交快照至少包含：

- 活动、学校、类别和稳定编码；
- 动态字段值；
- 参与者和成员资料版本；
- 通用表格数据；
- 附件逻辑版本和文件校验值；
- 承诺版本；
- 活动配置版本；
- 校验结果和提交人。

学校最终提交批次保存批次内全部作品快照引用和学校顺序，不能只保存一组可变化的作品 ID。

## 5. 评分和结果

- 评分草稿和正式提交具有不同状态。
- 签名评分表冻结服务端派生的有效评分、评分表模板、签名资源和时间。
- 替换个人签名不影响历史评分表。
- 评分汇总读取有效评分和历史签名快照，不临时重算为正式记录。
- 结果生成保存使用的评分版本、规则版本、异常预警、排序和奖项计算摘要。
- 发布只改变结果版本的公开状态，不重新计算。

## 6. 配置迁移

活动包导入生成来源快照和导入批次。导入到已有活动时，预览必须区分新增、可安全更新、已被引用、冲突和未知。应用成功后回读目标快照指纹。

## 7. 删除和保留

- 被历史快照引用的配置和资源不能物理删除。
- 逻辑删除不影响历史读取。
- 永久删除前执行影响检查，显示引用数量和代表性明细。
- 法定或主办方要求的保存年限由数据保留策略配置，但不得破坏审计链。

## 8. 禁止

- 只保存当前配置而不保存历史版本；
- 用名称代替稳定编码和版本引用；
- 通过修改旧 JSON 修复新业务需求；
- 发布时覆盖旧结果；
- 用前端缓存作为历史快照；
- 将临时导出布局反写为正式评分模板。
