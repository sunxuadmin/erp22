# CREHN 领域术语

## 1. 核心层级

| 术语 | 定义 | 稳定编码 |
|---|---|---|
| 赛事 `competition` | 长期赛事品牌，如“创意河南” | `competition_code` |
| 届次 `edition` | 某一届或某一年度赛事 | `edition_code` |
| 活动 `activity` | 一次可独立配置报名、审核、评审和发布的业务实例 | `activity_code` |
| 类别 `category` | 活动下的树形报送类别或大类 | `category_code` |
| 组别 `group` | 类别下用于名额、排序或展示的业务分组 | `group_code` |

关系为：一个赛事包含多个届次，一个届次可以包含一个或多个活动，一个活动包含类别树。

DYZ 的单个 `Activity` 导入时至少映射为 CREHN 活动；赛事和届次通过明确映射创建或匹配，不能依靠名称模糊合并。

## 2. 账号和组织

| 术语 | 定义 |
|---|---|
| 学校 | 具有稳定学校编码的数据归属单位 |
| 学校联络员 | 负责名单、学校审核和最终提交的学校账号 |
| 参赛者 | 使用本人激活账号填报本人作品的用户 |
| 省级审核员 | 进行形式审查的人员 |
| 评委/专家 | 只访问有效分配并完成评分的人员 |
| 次活动管理员 | 与活动管理员使用同一权限模型，但可按权限集合和数据范围缩减 |

学校、账号、角色是不同实体。角色不能代替学校归属，前端菜单不能代替后端数据范围。

## 3. 作品与提交

| 术语 | 定义 |
|---|---|
| 作品 `project` | 一个活动、学校和类别下的参赛记录 |
| 参与者资料 | 参赛者本人已确认的身份与联系资料 |
| 成员 | 作品中的作者、学生、指导教师、完成人或自定义成员类型 |
| 参赛者提交 | 参赛者将草稿提交给学校审核 |
| 学校推荐 | 学校审核通过某件作品，尚未形成最终批次 |
| 学校最终批次 | 学校按活动和类别统一提交的一组作品不可变快照 |
| 省级形式审查 | 对学校最终提交作品的资格、字段和材料进行正式审查 |

## 4. 评审与结果

| 术语 | 定义 |
|---|---|
| 审核任务 | 分配给省级审核员的工作范围 |
| 评审任务 | 分配给专家的活动、类别、项目或动态筛选范围 |
| 评分 | 一位专家对一件作品的可版本化评分记录 |
| 签名评分表 | 专家按类别统一提交后形成的不可变评分、模板和签名快照 |
| 评分汇总 | 只读查看各专家评分、签名和差异的审计页面 |
| 评审结果 | 按规则生成、锁定、发布和撤回发布的结果版本 |
| 展演顺序 | 结果发布后的独立排序数据，不回写作品填报数据 |

## 5. 配置与兼容

| 术语 | 定义 |
|---|---|
| 活动配置版本 | 活动、类别、字段、成员表、附件和规则的冻结版本 |
| 活动包 | 可移植的配置清单、资源和校验值集合 |
| 兼容适配器 | 将 DYZ 或旧 CREHN 格式转换为 CREHN 标准模型的边界组件 |
| 导入批次 | 一次预检、确认、写入、回读和审计的唯一记录 |
| 来源追踪 | 保存来源系统、来源记录编码、来源版本、校验值和导入批次 |
| 历史快照 | 在提交、签名或发布时冻结且不能被后续配置重解释的数据 |
