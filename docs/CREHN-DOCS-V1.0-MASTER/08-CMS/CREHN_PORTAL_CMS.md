# CREHN 独立门户与 CMS 规范 V1.1

## 1. 定位

CREHN 建设独立门户，不只是综合门户中的一个菜单入口。门户与业务后台共享认证入口和经过授权的公开数据 API，但采用独立路由、构建产物、域名/子域名配置和发布流程。

## 2. 内容模型

- 站点：名称、Logo、域名、主题、备案和默认 SEO；
- 栏目：树形分组、导航位置、排序、可见范围；
- 文章：标题、摘要、正文、封面、作者、来源、标签、置顶、发布时间；
- 媒体：图片、音视频、文档及版权/替代文本；
- Banner：图片/视频、链接、时间范围、排序；
- 首页组件：新闻、通知、活动、日程、媒体、数据卡片、成果展示、友情链接等；
- 页面：组件编排、数据源、样式令牌和发布版本。

## 3. 内容状态

```text
DRAFT → IN_REVIEW → SCHEDULED/PUBLISHED → OFFLINE → ARCHIVED
```

- 草稿、审核、发布和下线权限可分离；
- 支持立即和定时发布，定时任务必须记录执行结果；
- 发布生成不可变版本，回滚以历史版本创建新的发布；
- 已发布内容修改先形成新草稿，不直接覆盖线上内容。

## 4. 首页组件化

- 组件采用白名单注册，定义配置 Schema、数据源、响应式布局和降级样式；
- 管理员可拖拽排序、设置栅格、可见时间和受众范围；
- 组件不能执行任意脚本、SQL 或外部 HTML；
- 活动进度、报名数量、结果等业务数据由只读聚合 API 提供，CMS 不直接查询业务表；
- 配置非法、接口失败或媒体缺失时显示可控降级状态。

## 5. 权限与发布边界

- 超级管理员管理站点和全局组件；活动管理员管理本活动内容；
- 次活动管理员默认可配置为相同权限，也可减少到指定栏目、页面或动作；
- 内容审核员只能处理授权栏目，不能获得活动业务数据管理权限；
- 未发布、指定学校或登录后可见内容由服务端过滤；
- 预览链接短时有效、可撤销且不绕过内容权限。

## 6. 安全与合规

- 富文本采用白名单清洗，外链、iframe 和媒体协议受控；
- CMS 媒体统一进入文件扫描和版权/来源记录；
- 表单、搜索和评论类输入（若未来启用）必须防刷、限流和审计；
- SEO、站点地图、分享摘要不得泄露未发布活动或个人信息；
- 公开结果只读取已发布结果版本，不直接展示评分汇总草案。

## 7. DYZ 兼容范围

V1 兼容活动业务配置和可选的栏目/文章/媒体资源迁移，但不复制 DYZ 运行时页面布局、外链临时地址或数据库主键。CMS 导入需经过栏目映射、资源重建、链接检查和发布前人工预览。

## 8. 验收

- 草稿不可被匿名访问，定时发布/下线准确，回滚后内容和媒体一致；
- 多端响应式、图片替代文本、键盘导航和基础 SEO 可用；
- 组件异常不拖垮整页，缓存更新后能读到正确发布版本；
- 站点管理员、活动管理员、内容审核员的数据范围互相隔离。
