# CREHN 主题与文件系统规范 V1.1

## 1. 主题体系

主题使用语义化设计令牌，不把颜色和阴影散落在页面组件中。至少包括：

- 品牌色、强调色、文本、背景、边框、成功/警告/危险；
- 字体、字号、行高、间距、圆角、阴影；
- 菜单、卡片、表格、日历和门户组件令牌；
- 浅色/深色及高对比模式；
- 桌面和窄屏布局断点。

“液态玻璃”等视觉方案可以作为预设主题，但必须提供低透明度、低性能设备及不支持滤镜浏览器的稳定回退，不作为业务信息层级的唯一表达。

管理员只能通过类型化主题令牌和预设维护样式，不开放任意 CSS、JavaScript、外链脚本或可执行表达式。主题调整不得改变权限、数据范围、字段校验、状态转换和审计要求。

## 2. 配置作用域

- 门户主题：按站点和发布版本生效；
- 全局工作台主题：按系统或活动生效；
- 角色工作台布局：按活动与角色生效；
- 用户偏好：只影响个人列宽、折叠和密度；
- 业务规则：字段、附件、评分、状态等不得写入主题配置。

作用域必须在配置页明确显示，避免出现多个“看似相同、实际不同”的有效配置源。

用户偏好只有在管理员允许时生效，且不能覆盖已发布的品牌区、导航模式、菜单/组件可见性、按钮显示和活动主题。临时偏好清除后必须恢复当前已发布角色配置。

## 3. 系统骨架与品牌区

角色工作台支持左侧导航、混合导航和顶部导航三种系统骨架。按活动与角色配置品牌区、Logo、品牌文字来源、侧栏折叠行为、顶栏高度、侧栏宽度、内容宽度、菜单密度、面包屑和页面标签栏。

门户骨架、门户主题和后台工作台骨架分别发布；可以共享活动 Logo 和品牌基础信息，但任一侧发布不得无版本地覆盖另一侧布局。

系统骨架使用稳定 `role_key` 和布局版本，不保存角色数字 ID、菜单数字 ID或用户本地路径。菜单只消费服务端授权结果，配置只能调整已授权菜单的分组、名称、图标和顺序。

## 4. 发布、预览和回滚

- 主题草稿支持预览和多分辨率检查；
- 发布生成不可变版本，记录操作者、时间、差异和回滚来源；
- 页面加载失败或配置非法时使用系统安全默认主题；
- 回滚创建新发布版本，不篡改历史版本。

预览至少覆盖系统默认、活动、角色、页面和类别覆盖后的最终合并结果，并可选择目标角色和受支持分辨率。发布前必须拒绝未知令牌、非法尺寸、失效资源和超出白名单的配置项。

## 5. 文件边界

统一 `FileService` 负责：

- 静态资源、CMS 媒体、模板、报名附件、评分签名表、结果文件和临时文件；
- 上传会话、哈希去重、扫描、预览/转码、授权下载、回收和清理；
- 文件元数据与业务绑定关系；
- 本地开发与对象存储实现适配。

业务表只保存 CREHN 文件标识和绑定信息，不保存 DYZ OSS ID、外部 bucket 路径、临时签名 URL 或用户本地路径。

完整状态和授权规则见 [文件生命周期](CREHN_FILE_LIFECYCLE.md)。
