# CREHN Codex 项目记忆

本目录是跨会话长期有效信息的统一入口。聊天记录只作为临时上下文，不作为需求、决策或验收的唯一证据。

## 阅读顺序

1. 根目录 `AGENTS.md`
2. 根目录 `TASKS.md`
3. `PROJECT_STATUS.md`
4. `TASK_BOARD.md`
5. 当前活动任务卡
6. 与任务直接相关的 MASTER 专题规范
7. `DECISIONS.md` 与 `HANDOFF.md`

## 文件职责

- `PROJECT_STATUS.md`：项目基本信息、模块状态、当前工作、冻结契约和风险。
- `TASK_BOARD.md`：去重后的统一任务清单；状态只使用规定的七种值。
- `DECISIONS.md`：会影响后续实现的已确认决策和待确认冲突。
- `HANDOFF.md`：新会话可直接使用的当前交接快照。
- `SESSION_INDEX.md`：按主题索引历史工作及其沉淀位置。
- `ARCHIVE_PLAN.md`：会话保留、暂留、归档、删除门禁和三会话机制。

## 证据与更新规则

- 代码/测试结果优先于任务卡，最新冻结任务卡优先于正式文档，正式文档优先于 Git 历史和较早会话。
- `IMPLEMENTED` 只代表实现完成；浏览器、数据库、服务器、部署和生产验收必须分别给出证据。
- 不能确认的内容写为“待确认”，不得凭聊天记忆删除旧方案。
- 每次完成任务后更新任务卡、`TASK_BOARD.md` 和 `HANDOFF.md`；跨模块且难以回退的决策再更新 `DECISIONS.md`。
- SQL、服务器连接、部署、Git提交、Git推送、外部发送和会话/文件删除分别需要明确授权。
