## 1. 项目基本信息

### 定位

CREHN 是“创意河南”省级高校艺术设计赛事平台。系统包含独立公共门户、管理端/角色工作台、后端业务模块和独立部署资产，覆盖学校/账号准备、参赛者本人激活与填报、学校审核推荐和最终批次提交、省级形式审查、专家评审、分数汇总、结果生成与发布。

DYZ 仅作为功能参考和兼容输入。CREHN 不与 DYZ 共库、双写或复用生产标识、密钥和部署路径。

### 技术栈与目录

| 范围 | 当前实现 |
| --- | --- |
| 后端 | RuoYi-Vue-Plus 5.6.1、Java 17、Spring Boot 3.5.14、MyBatis-Plus 3.5.16，模块化单体 |
| Web 管理端 | Vue 3.5、TypeScript 5.9、Vite 7、Element Plus、Pinia、Vitest、pnpm |
| 公共门户 | Vue 3.5、TypeScript、Vite 6，独立构建和运行时配置 |
| 数据与基础设施 | MariaDB、Redis、私有对象存储；TEST 使用 MinIO，PROD 目标为 OSS |

仓库内未找到根目录 `README.md` 和 `docs/project/`；本状态以 `AGENTS.md`、MASTER 规范、需求索引、任务卡、模块 README、部署资产和实际代码为准。

### 运行、开发、测试、构建与部署

- 管理端：在 `frontend/` 使用 `pnpm dev`；测试 `pnpm test`，类型检查 `pnpm typecheck`，生产构建 `pnpm build:prod`。
- 门户：在 `portal/` 使用 `pnpm dev`；构建 `pnpm build` 或 `pnpm build:static`。
- 后端：Java 17/Maven 多模块构建；部署 Dockerfile 使用 Maven 校验和打包。本机缺少工具时必须记录为 `NOT_RUN`，不得用单文件编译代替模块验证。
- 本地/TEST：Compose 运行 MariaDB、Redis、后端和 Web；TEST 项目名 `crehn-test`，部署根 `/srv/crehn-test`，端口 28181/29000/29001。
- 部署统一入口：`deploy/scripts/invoke-deployment.ps1`。预检、构建、资产暂存、部署、验证、数据库计划/初始化和回滚均为独立动作；写操作需要 `-Apply`、确认文本及对应授权。
- PROD：目标为专用 ECS 2，仅接收经 TEST 验证的同一不可变镜像/资产，不在生产主机从源码构建。

## 5. 冻结契约

### 稳定标识与配置

- 跨环境/导入导出使用 `competition_code`、`edition_code`、`activity_code`、`category_code`、`field_key`、`member_type_code`、`table_key`、`file_requirement_code`、`school_code`、`role_key`、`rule_code`、`resource_key`、`template_code`、`notification_template_code`、`page_key`、`component_key`、`action_key`；不得使用本地数字主键作为可迁移标识。
- UI 配置继承顺序为：系统 → 活动 → 角色 → 页面 → 类别；只能保存白名单字段，不允许任意 CSS、JavaScript、HTML、SQL 或 iframe。
- `sys_workbench_layout` 的目标唯一键为 `(tenant_id, role_key, component_key)`；稳定配置键为 `crehn.workbench.role.shell.<role_key>`。

### API、权限与路由

- 当前实际控制器路径为 `/crehn/<module>`；Web 通过 `/prod-api/` 代理，管理端部署上下文为 `/admin/`，公共门户目标路径为 `/crehn/`。
- 权限标识一般为 `crehn:<module>:<action>`；`system:homeConfig:*`、`system:workbench:edit` 等现有例外必须显式维护，不得用前端可见性替代服务端权限。
- DOC-001 已消除 `/api/v1` 与当前代码的文档冲突；新路由继续使用 `/crehn/<module>`。

### 数据与版本

- `deploy/db/migration-manifest.json` 当前 `schemaVersion = 1`，业务结构项为44；Docker `/opt/crehn/init` COPY 为47（1基线 + 2 bootstrap + 44业务结构）。历史“45条”只作为加入 V006/V007 前的时点证据。
- 活动/兼容包当前使用 `formatVersion = 1.0`；工作台头部布局 `layoutVersion = 8`；门户发布快照支持 `renderVersion` v1/v2 兼容。
- V005 新增稳定 `role_key`；V006 新增 `portal_page_layout`；V007 收紧学校/分数汇总默认权限。三者均不能因脚本存在而视为已执行。
- 已提交批次、已签名评分表和已发布结果版本为不可变快照；纠错必须走新版本/审计流程。

### 角色、流程与边界

- 参赛者必须本人激活和填报；学校负责名单、审核/推荐和最终批次提交，不能静默代替本人填报。
- 权限由功能权限、角色身份、业务数据范围和业务状态共同决定；前端隐藏按钮不是授权证据。
- 分数汇总与结果生成/发布是不同职责；专家只能看到本人任务，学校只能看到本校范围。
- 文件默认私有，下载通过受控接口/短时授权；不得暴露永久公共直链。
- DYZ 只允许通过版本化适配/导入导出兼容；不共库、不双写、不复制数字主键、密钥、生产配置或部署路径。
