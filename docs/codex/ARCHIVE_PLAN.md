# CREHN Codex 会话精简与归档方案

> 原则：先沉淀，再归档；优先归档，不轻易永久删除。本文件只给建议，不执行重命名、归档或删除。

## 必须保留的长期顶层会话

1. **`00-项目总控调度`**
   - 唯一项目入口和任务主表所有者。
   - 负责读取任务卡、分析影响面、分配子代理、汇总结论、更新 `TASK_BOARD.md` 和 `HANDOFF.md`。
   - 建议将当前“00-项目会话整理与总控”人工改名为此名称。

2. **`10-集成联调`**
   - 只负责前后端、Android/后端（若未来 CREHN 确有 Android 客户端）、构建/测试失败、环境问题和部署前验证。
   - 不维护独立总任务板，不自行授权服务器/数据库/部署。

3. **`90-审查与发布`**
   - 只负责 Git diff、权限、安全、SQL、发布、回滚和最终验收审查。
   - 审查通过不自动等于 Git、SQL、服务器或部署授权。

当前不建议增加其他长期顶层会话。

- 任何与当前 `git status` 未提交文件直接相关、且尚未完成信息提取的会话。

## 可以归档

符合以下任一情形且不存在未沉淀信息时，优先归档：

- 任务已经完成，代码/测试/任务卡/Git 已能独立追溯。
- 内容已被 `PROJECT_STATUS.md`、`DECISIONS.md`、任务板或活动/归档任务卡承接。
- 与其他会话高度重复，且不再拥有独立未完成任务。
- 旧实现或旧部署步骤已被新的可验证实现替代。
- 只承担过临时分析、分类提交或一次性故障排查。

当前可优先归档：

- **“分析活动创建方案”**：有效决策与冲突已转入 `DECISIONS.md` 和任务板。
- **“按会话内容分类提交 Git”**：提交与远端信息已有 Git/文档证据。
- 已完成的 TEST 预检、0.1.9 构建部署、配置运行时修复等临时会话（人工核对无未提交上下文后）。
- 多个泛化“会话管理/分工”会话；本文件和三会话机制已成为单一现行规则。

## 可以删除的严格门禁

只有同时满足以下条件才建议永久删除：

1. 完全是空白、失败测试、重复创建或无效会话；
2. 没有独立决策、接口/数据契约或禁止事项；
3. 没有未完成任务、未提交修改或恢复价值；
4. 所有有效信息已写入仓库并经人工抽查；
5. 删除不影响审计、发布或问题追溯。

**本轮不建议永久删除任何具体 CREHN 会话。** 原因是只读取到最近任务索引和部分回合，无法证明所有旧会话均满足五项条件。

## 归档前检查表

- [ ] 该会话关联的任务编号唯一，状态已写入 `TASK_BOARD.md`。
- [ ] 决策/契约/禁止事项已写入任务卡或 `DECISIONS.md`。
- [ ] 当前 `git status` 中没有只能由该会话解释的改动。
- [ ] 测试、浏览器、数据库、服务器和生产证据分别标记。
- [ ] `HANDOFF.md` 能让新会话继续工作。
- [ ] 未授权操作没有被误写为已完成。

## 固定工作机制

```text
用户新任务
  → 00-项目总控调度：选择唯一任务编号、创建/更新任务卡、分解子任务
      → 子代理：在限定范围内分析/实现，并把结论回写任务卡
      → 10-集成联调：只处理联调、构建、测试和环境证据
      → 90-审查与发布：只做 diff/权限/SQL/发布/回滚审查
  → 00-项目总控调度：合并证据、更新 TASK_BOARD/HANDOFF、决定归档
```

- 普通开发任务不再创建长期顶层会话。
- 所有状态以仓库任务板为准，会话标题不充当任务状态。
- 每次结束必须留下“修改范围、验证、未验证、风险、下一步、授权状态”。
- 若子代理结论未回写任务卡或 `HANDOFF.md`，该工作视为未完成交接。
