# ADR-0001 独立 Compose 与不可变产物晋级

- 状态：`CONFIRMED`
- 日期：2026-07-30
- 关联需求：`REQ-007`、`REQ-009`、`REQ-010`、`REQ-012`

## 决策

1. CREHN 使用独立代码、数据库、Redis、对象存储、网络、卷和部署配置。
2. LOCAL 负责开发；192.168.2.229 的 `crehn-test` 负责构建和集成测试；资源允许时增加独立 `crehn-stage`；新建且专用于 CREHN 的阿里云 ECS 2 为 `crehn-prod`，其地址和认证信息只能来自受限环境文件。
3. 测试通过后发布相同 Docker 镜像版本/摘要到生产；生产不构建源码。
4. 初期使用带 SHA-256 的镜像归档传输，私有 Registry 另行决策。
5. 1Panel 不是运行依赖。若以后采用，只安装在宿主机并受限访问，不安装进 CREHN 容器。
6. Compose、迁移清单和镜像版本由 Git 管理；真实密钥和环境文件不进入 Git。
7. TEST 使用独立 MinIO；PROD 使用阿里云 OSS且不部署MinIO。SSH控制配置、TEST运行配置和PROD运行配置分别隔离。

## 原因

- 避免 DYZ 与 CREHN 端口、容器名、数据库、缓存和文件相互污染；
- 保证测试和生产使用同一不可变产物；
- 避免在生产服务器构建及手工修改容器产生配置漂移；
- 保持部署工具可审计、可回滚且不依赖管理面板。

## 后果

- 服务器实施前必须核验资源、端口、Docker/Compose和主机指纹；
- 数据库、对象存储和密钥不能随镜像复制；
- 日常更新切换镜像版本并执行受控迁移，不修改运行容器内源码；
- Git推送、测试部署和生产部署继续使用独立授权。
